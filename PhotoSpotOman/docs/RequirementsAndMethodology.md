# PhotoSpotOman - Requirements & Methodology

## 1. Requirements Gathering & Analysis

PhotoSpotOman is a web-based platform designed for discovering and sharing photography locations across Oman. The requirements gathering process involved multiple techniques to ensure comprehensive understanding of stakeholder needs. Stakeholder interviews were conducted with photographers, tourists, and potential administrators to identify their expectations and pain points. Document analysis was performed by reviewing similar platforms such as ShotHotspot and PhotoHound to understand industry standards and best practices. Brainstorming sessions helped generate innovative feature ideas for spot sharing and discovery, while prototyping allowed early validation of user interface designs with stakeholders.

The functional requirements identified for the system include user registration and authentication, allowing both regular users and administrators to access the platform securely. Contributors can create new photography spots by providing detailed information including name, description, GPS coordinates, and region. The system supports multiple image uploads per spot, enabling photographers to showcase different angles and conditions of each location. Users can search and filter spots by category and location to find relevant photography destinations. Social interaction features allow users to like and comment on spots, fostering community engagement. The administrative workflow includes spot approval and rejection functionality, ensuring content quality control before public visibility. Administrators can also manage categories to organize spots effectively. Users can track their submitted spots and view their approval status through a dedicated dashboard.

Non-functional requirements address system performance, security, and usability concerns. The system must respond within three seconds to ensure a smooth user experience. Password security is implemented using industry-standard hashing algorithms to protect user credentials. The platform is designed to support multiple concurrent users without performance degradation. The user interface is responsive and mobile-friendly, accommodating users on various devices. All communications are secured using HTTPS protocol. Database integrity is maintained through proper foreign key constraints and cascading rules. Image storage uses unique identifiers (GUIDs) to prevent naming conflicts and ensure data integrity.

Three distinct user roles were identified during the analysis phase. Guests are anonymous visitors who can browse approved spots and register for an account. Contributors are registered users who can create spots, upload images, like and comment on content, and manage their own submissions. Administrators have full system access including content moderation, approval workflows, and category management capabilities.

## 2. Methodology Used (SDLC Model)

The PhotoSpotOman project follows an Agile Iterative Software Development Life Cycle (SDLC) model. This methodology was chosen due to its flexibility in accommodating changing requirements, which is essential for a community-driven photography platform where user needs evolve based on feedback. The iterative approach allows features to be delivered in working increments, enabling stakeholders to see progress and provide input throughout the development process. Early and continuous user involvement helps validate design decisions and reduces the risk of building features that don't meet actual needs. The short iteration cycles also help identify and address issues early before they become costly to fix.

The development was organized into five sprints, each focusing on specific functionality. The first sprint established the core project structure, database design using Entity Framework Core migrations, and implemented the authentication system with cookie-based security and role-based authorization. The second sprint focused on spot management, implementing CRUD (Create, Read, Update, Delete) operations for photography spots along with the image upload functionality that stores files on the server and metadata in the database. The third sprint added user interaction features including the like/unlike toggle system and commenting functionality, as well as search and filtering capabilities. The fourth sprint delivered administrative features including the spot approval and rejection workflow, category management, and feedback management for moderating comments. The fifth and final sprint focused on user interface improvements, comprehensive testing, and deployment preparation.

The technical implementation follows the Model-View-Controller (MVC) architectural pattern using ASP.NET Core 8.0 framework. SQL Server serves as the database backend, accessed through Entity Framework Core as the Object-Relational Mapper (ORM). The frontend is built using Razor Views with Bootstrap 5 for responsive styling and jQuery for client-side interactions. Authentication is implemented using ASP.NET Core's cookie authentication middleware with claims-based role authorization supporting three policies: AdminOnly, ContributorOnly, and AnyRole. Version control is managed through Git to track changes and enable collaboration.

Key Agile practices applied throughout the project include iterative development with features built incrementally across sprints, continuous integration with regular code commits and testing, focus on delivering working software at the end of each iteration, simplicity by prioritizing essential features before adding enhancements, and technical excellence through clean code practices and proper architectural patterns. This approach ensured the successful delivery of a functional photography location sharing platform that meets the identified requirements while remaining adaptable to future enhancements.

## 3. Training Plan

The PhotoSpotOman platform was designed with usability in mind, minimizing the need for extensive user training. The intuitive user interface follows familiar web conventions, allowing guests and contributors to navigate the system with ease. Standard patterns such as registration forms, search bars, and card-based layouts ensure that users can quickly understand how to browse spots, create accounts, and interact with content without formal instruction. Tooltips and placeholder text provide contextual guidance where needed, helping users complete actions like spot submission and image uploads successfully on their first attempt.

Administrator training focuses on the dashboard functionalities and content moderation workflow. A walkthrough session covers the approval and rejection process for pending spots, category management operations, and feedback moderation capabilities. Administrators learn to filter spots by status, review submission details, and make informed decisions about content visibility. Documentation is provided outlining step-by-step procedures for common administrative tasks, ensuring consistent content quality across the platform. Knowledge transfer sessions ensure that technical staff understand the system architecture, database structure, and deployment procedures for ongoing maintenance and future enhancements.

## 4. Feedback

Feedback collection is integral to the continuous improvement of the PhotoSpotOman platform. During the development phase, stakeholder review sessions were conducted at the end of each sprint to gather input on delivered features. Photographers and potential users provided valuable insights on the spot submission workflow, search functionality, and user interface design. This feedback was incorporated into subsequent iterations, ensuring the final product aligns with user expectations and needs.

Post-deployment feedback channels include the commenting system on spots, allowing users to share their experiences and suggestions within the community. A contact form enables users to communicate directly with administrators for support requests, feature suggestions, or issue reporting. User activity patterns and engagement metrics are monitored to identify popular features and areas requiring improvement. Regular review of feedback submissions helps prioritize future enhancements and ensures the platform evolves to meet the growing needs of the photography community in Oman.

## 5. Testing

A comprehensive testing strategy was implemented to ensure the reliability, security, and performance of the PhotoSpotOman platform. Manual testing was performed throughout development, with each feature thoroughly tested against its requirements before integration. Test cases covered all user workflows including registration, login, spot creation with image uploads, searching and filtering, liking, commenting, and administrative approval processes. Edge cases such as invalid inputs, empty submissions, and unauthorized access attempts were systematically tested to ensure proper error handling and validation.

Security testing verified the authentication and authorization mechanisms, confirming that password hashing functions correctly, session management is secure, and role-based access control properly restricts functionality. Attempts to access admin-only features without proper credentials were tested to ensure the system responds appropriately with forbidden access pages. Browser compatibility testing ensured consistent functionality across major browsers including Chrome, Firefox, Edge, and Safari, while responsive design testing confirmed proper display on desktop, tablet, and mobile devices. Performance testing evaluated page load times and system responsiveness under typical usage conditions, ensuring the platform meets the three-second response time requirement established in the non-functional requirements.
